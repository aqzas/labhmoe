# 网站加载优化与维护

2026-10-13 为站点实际引用的静态图片生成 WebP 展示版本。原始图片保持原路径，新闻详情中的原图下载链接仍指向原文件。动画 GIF 保持原格式。

## 图片处理

`tools/optimize_images.py` 读取页面、成员、新闻及数据文件中的图片引用，生成 `images/optimized/` 下的多尺寸 WebP，并更新 `_data/image_assets.json`。文件名包含原图内容和压缩参数的摘要，替换原图后可生成新地址，避免命中旧缓存。

图片组件通过 `_includes/image-attributes.html` 输出 `srcset` 和 `sizes`，浏览器按实际显示宽度及像素密度选择版本；没有索引的图片继续使用原路径。头像最大宽度 800 像素，一般配图 1920 像素，报纸版面 2400 像素；科研图和报纸使用更高的压缩质量。`_includes/background-image.html` 为背景图选择 WebP，手机使用较小版本。

新增或替换图片后，在已安装 Pillow 的 Python 环境运行：

```sh
python tools/optimize_images.py
```

将原图、生成的 WebP 和图片索引一并提交。脚本不会删除原图或旧展示版本。`tools/` 已从网站输出排除。

## 脚本与字体

Popper 2.11.8、Tippy 6.3.7 和 Mark.js 8.11.1 保存在 `assets/lib/`，与网站同源加载；相应许可文件一并保留。升级时使用对应版本的官方发行文件并保留许可。

除用于首屏主题恢复的 `dark-mode.js` 外，脚本使用 `defer`。搜索、提示、表格处理等在 DOM 就绪后初始化，不再等待大图片加载。搜索输入等待时间由 1000 毫秒缩短为 200 毫秒，并通过读取 `textContent` 减少筛选时的布局计算。

Google Fonts 和代码高亮样式采用非阻塞加载；字体尚未到达时使用系统后备字体。页眉背景图按屏幕宽度预加载。站点仍有外部字体及图标资源请求，其可用性取决于访问网络。

## 验证范围

使用本地 HTTP 服务和 Chrome 检查首页、Team、Projects、Research、Contact、GCP 和 News 的桌面及手机布局，记录浏览器实际请求的图片字节数，并检查图片、搜索与高亮、产品筛选、手机导航、深浅主题和无 JavaScript 展示。对比数字反映图片传输量，不能直接换算为线上加载时间。

1280 × 900、像素密度 1、空缓存下，首屏及浏览器自动预取附近区域的图片请求如下。两组使用相同页面内容，分别加载原图和优化版本；MB 按十进制计算。

| 页面 | 原图方案 | 优化版本 |
| --- | ---: | ---: |
| 首页 | 9.80 MB | 0.293 MB |
| Team | 62.23 MB | 0.304 MB |
| Projects | 14.38 MB | 0.311 MB |
| Research | 1.98 MB | 0.185 MB |
| Contact | 1.88 MB | 0.129 MB |
| GCP | 1.09 MB | 0.106 MB |
| News | 1.18 MB | 0.114 MB |

375 × 900、像素密度 1 下：首页从 3.20 MB 降至 0.120 MB，Team 从 8.85 MB 降至 0.115 MB。额外验证了图片请求尚未完成时搜索可用，以及响应式图片加载失败时能正确使用占位图。

当前本地组件预览使用 LiquidJS 和 Markdown 适配器；发布前仍需通过仓库的正式 Ruby/Jekyll 构建。
