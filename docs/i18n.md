## 页面配对

页面开头设置 `lang` 和 `translation_key`。同一内容的两种语言共用一个 `translation_key`，每个语言只能有一个对应页面。

```yaml
---
title: News
lang: en
translation_key: news
nav:
  order: 4
  tooltip: Latest news and activities
---
```

```yaml
---
title: 新闻动态
lang: zh-CN
translation_key: news
nav:
  order: 4
  tooltip: 最新新闻与学术活动
---
```

`_config.yaml` 设置默认语言为英文，并为 `zh/` 目录设置中文默认值。主要页面仍显式写出语言，便于检查配对。`_includes/language-switch.html` 在普通页面和新闻集合中查找配对项；导航仅显示当前语言的页面。

切换使用普通链接，不需要 JavaScript，也不根据浏览器语言或历史选择强制跳转。访问者打开的地址决定当前语言。链接使用 `relative_url`，支持 GitHub Pages 子目录部署。

## 未翻译内容

现有新闻正文保留中文，新闻摘要会标明跨语言内容。团队列表按页面语言显示中文或英文姓名。成员仅通过团队列表展示，不生成独立资料页，头像和姓名不再链接至个人页面。论文题名、作者、期刊、DOI 等保留发表时的原文。

没有对应译文时，新闻详情页的切换入口明确显示另一语言的新闻栏目名称，例如“中文新闻”或“EN · News”；其他页面回到另一语言的首页。只有真实存在的译文才会作为对应语言页面加入 `hreflang`。

后续翻译新闻时，为译文设置独立地址、正确的 `lang`，并与原文使用相同的 `translation_key`。如把译文也加入新闻集合，需同步调整新闻列表的筛选规则，避免两种语言在列表中重复出现。

## 公共文案和数据

- `_data/i18n.yml`：导航辅助文字、搜索、筛选、页脚、职位名称和原文语言提示。
- `_data/projects.yaml`：原有 `title`、`subtitle`、`description` 为中文，新增的 `title_en`、`subtitle_en`、`description_en` 为英文。图片、链接和标签共用。
- `_data/trials.yml`：原有 `title`、`indication`、`intervention`、`phase` 为中文；`english_title`、`indication_en`、`intervention_en`、`phase_en` 为英文。注册号、注册链接、排序和产品类别共用。
- 微信文章在中英文新闻页分别维护展示标题，链接指向原来的中文文章。英文页注明链接文章为中文。

更新项目或试验时，请同步更新双语字段。成员档案 `_members/*.md` 中的 `name` 保留英文姓名，`name_zh` 保存经确认的中文姓名；中文团队页优先显示 `name_zh`，缺少时回退到 `name`。现有 35 名成员的中文姓名已按用户提供的名单对应，新增成员时也应核对正式名单，不根据拼音猜测汉字。

`_config.yaml` 中的 `collections.members.output` 已设为 `false`。保留 `_members/` 作为团队卡片的数据来源；正式重新构建并部署后，原有成员资料页不再输出。

## 本次检查

本地使用 LiquidJS、Markdown 适配器和 Dart Sass 生成预览，再由 Chrome 检查实际页面行为。覆盖 14 个栏目页面的 1280、768、375 像素布局，导航语言、来回切换、站内链接、搜索与提示、临床试验筛选、主题切换，以及无 JavaScript 场景。另检查带 `baseurl` 的子目录部署和未翻译详情页的回退链接。

本地预览不等同于 Ruby/Jekyll 正式构建。当前环境没有 Ruby/Bundler，正式构建仍由仓库现有的 GitHub Actions 工作流执行。具备 Ruby 环境时可在仓库根目录运行：

```sh
bundle install
bundle exec jekyll build
bundle exec jekyll serve
```

打开 `/` 和 `/zh/` 即可查看两种语言。
